# Contributing to Awesome MeetKai

Thanks for your interest in contributing! We want this to be a collection of **real, tested deployments** — not hypotheticals.

## What We Accept

### Use Cases
- Real OpenClaw deployments you've run
- Must be tested for at least a week
- Include architecture, gotchas, and lessons learned
- Failures are as valuable as successes

### Skills
- Working OpenClaw skills
- Must include SKILL.md documentation
- Test cases required

### Patterns
- Architectural patterns that emerged from real use
- Anti-patterns and what to do instead
- Performance optimizations

## What We Don't Accept

- ❌ Hypothetical or planned projects
- ❌ Crypto/trading automation
- ❌ Anything requiring sensitive credentials in code
- ❌ Use cases that violate platform ToS

## How to Contribute

### Adding a Use Case

1. Fork the repo
2. Create `usecases/your-use-case.md`
3. Use this template:

```markdown
# Use Case Name

> One-line description.

## Overview
What does it do? How long has it been running?

## Architecture
Diagram or description of how it works.

## Setup
How to replicate it.

## Results
What did you achieve?

## Gotchas
What went wrong? What would you do differently?

## Files
Key files and their purposes.
```

4. Add it to the README.md table of contents
5. Submit a PR

### Adding a Skill

1. Create `skills/skill-name/SKILL.md`
2. Include example usage
3. Add to the skills table in README.md
4. Submit a PR

### Improving Docs

- Fix typos, clarify confusing sections
- Add missing details
- Update outdated information

## Code of Conduct

- Be helpful
- Share honestly (including failures)
- Credit sources

## Questions?

Open an issue or reach out on [Discord](https://discord.gg/openclaw).
